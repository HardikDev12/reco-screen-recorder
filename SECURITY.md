# Security Policy

## Reporting Security Issues

We take the security and integrity of RECO seriously. If you discover a potential vulnerability or security flaw, we appreciate your help in disclosing it to us responsibly.

---

### Supported Versions

Only the latest release of RECO receives security patches:

| Version | Supported |
|---|---|
| 1.0.x | :white_check_mark: |
| < 1.0.0 | :x: |

---

### How to Report a Vulnerability

**Please do NOT disclose security vulnerabilities publicly in public GitHub issues.**

To report a vulnerability responsibly:
1. Navigate to the GitHub repository Security Advisory page: [https://github.com/HardikDev12/reco/security/advisories/new](https://github.com/HardikDev12/reco/security/advisories/new)
2. Provide a detailed summary including:
   - Type of vulnerability (e.g., privilege escalation, path traversal, IPC injection).
   - Step-by-step reproduction instructions or Proof of Concept (PoC).
   - Impact assessment on end-user systems.
   - Affected operating system versions.

---

### Response Process
* **Acknowledgment**: We aim to acknowledge valid reports within 48 to 72 hours.
* **Triage & Remediation**: If confirmed, a fix will be developed and published in the subsequent release.
* **Public Disclosure**: Coordinated disclosure will occur after an update addressing the issue is made available.
